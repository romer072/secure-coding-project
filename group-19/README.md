## Build

```sh
make all
```

This produces the `bun_parser` executable in this directory.

## Run

```sh
./bun_parser path/to/file.bun
```

For valid files, the parser prints a summary containing the file size, BUN header
fields, each asset record, bounded previews of asset names and data payloads,
and the number of assets parsed.

For malformed or unsupported files, the parser prints as much safe information
as possible, then reports a diagnostic error with the result category and byte
offset where applicable.

## Parser Behaviour

The parser treats all BUN input as untrusted binary data. It avoids direct struct
casts from file bytes and decodes little-endian fields explicitly.

Implemented validation includes:

- BUN magic and supported version checks.
- Section alignment, size, EOF, and overlap checks.
- Checked integer arithmetic for offset and size calculations.
- Asset name bounds, non-empty names, and printable ASCII validation.
- Asset data bounds validation.
- Raw and RLE asset preview output.
- RLE stream validation, including zero-count rejection and expanded-size checks.
- CRC-32 validation for assets with non-zero checksums.
- Safe rejection of zlib compression, unknown compression values, and unknown
  flag bits.

## Test

Install test dependencies if needed:

```sh
./setup.sh
```

Run the normal test suite:

```sh
make clean test
```

Run sanitizer and Valgrind checks:

```sh
make test-sanitize
make test-valgrind
```

The current suite contains 36 Check tests. It covers valid files, malformed
files, boundary cases, unsupported features, RLE validation, CRC-32 validation,
and generated overflow cases.

Test fixtures are generated by `tests/generate_fixtures.py` when `make test`,
`make test-sanitize`, or `make test-valgrind` is run. The generated `.bun` files
live under `tests/samples/` temporarily and are removed by `make clean`.

## Clean

```sh
make clean
```

This removes generated binaries, test runners, sanitizer binaries, generated
test samples, fixture stamps, and Python cache files.
